## What went well

- **Ports-first LLM integration:** Nest wiring stays thin; **`ReportService.summarizeObservations`** delegates to **`AiSummarizer`**—consistent with Epic 2’s extractor pattern.
- **Error contract reuse + extension:** Upload envelope patterns extended with summarize-specific **`details.code`** values and filter mappings (**`SUMMARIZATION_*`**) so clients are not surprised by opaque **500**s for known failures.
- **Intentional deferral of flaky CI:** **5.4** documented deferral of full HTTP summarize e2e until a mock existed; **5.5** executed that plan instead of bolting on flaky live-LLM jobs.
- **OpenAPI discipline:** **`npm run openapi:check`** kept **`openapi/openapi.json`** aligned with decorators—including summarize-specific **400** example after review (**`SUMMARIZATION_BODY_INVALID`**).
- **Story 5.5 review closure:** One focused **patch** strengthened the contract without scope creep.
- **Reuse of existing e2e harness:** Second **`overrideProvider`** on the same **`AppModule`** test module mirrors **`PDF_OBSERVATION_EXTRACTOR`**—low ceremony, high signal.

---

## Challenges and friction

- **Two layers of error semantics:** Controllers choose HTTP status + Nest exception payload; **`http-exception.filter`** maps **`details.code`** → top-level **`error.code`**. Tests must assert **both** when locking client JSON—easy to drift if copy changes.
- **OpenAPI example drift:** Early **5.4** review caught upload-oriented **400** example on summarize; worth a quick “does this example match runtime?” pass whenever decorators change.
- **Epic 4 retro artifact gap:** Sprint shows **`epic-4-retrospective: done`**, but no **`epic-4-retro-*.md`** sits beside **Epics 1–3** retros in `implementation-artifacts`—continuity for “what we promised last epic” is weaker unless another log exists.
- **Optional vs mandatory test matrix:** **5.5** consciously skipped duplicate **429** summarize matrix; rationale is sound, but future readers should not confuse “not tested” with “not supported.”

---

## Key insights

1. **Treat non-deterministic dependencies as a test-design input:** If a feature needs a network or GPU, ship **contract value** first with **mocks**, then add optional manual/heavy integration—don’t block merges on them.
2. **`parseAndValidateSummarizeBody` is part of the public contract surface:** Reusing it inside e2e assertions couples tests to validation rules in a **good** way: if validation changes shape, tests should fail until expectations update.
3. **Filter + controller matrix belongs in one mental model:** Any new **`SummarizationProviderError`** code needs **controller mapping**, **filter top-level mapping**, **OpenAPI** example, **failure matrix** row, and **tests**—checklist-style consistency beats one-off fixes.
