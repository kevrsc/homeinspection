## What went well

- **Ports/adapters discipline:** `PdfObservationExtractor` + Nest DI token kept PDF technology and orchestration testable; timeouts and mocks plugged in without rewriting HTTP contracts.
- **Contract determinism stack:** Global error envelope, typed failure details, OpenAPI generation/check path, and Story 2.9’s failure matrix + fixtures + bidirectional matrix alignment tests reinforced the same truth in multiple places.
- **Operational clarity:** Structured logging (2.7) tied outcomes to request correlation already established in Epic 1.
- **Review loops that hardened artifacts:** Story 2.9 demonstrated effective patch batches (inline examples, missing-file fixture, strict matrix equality, per-fixture shape asserts).
- **Clean epic closure:** Story 2.10 documented persistence/async/AI/future-HTTP seams **without** dormant infra or new dependencies—matching NFR17 and FR37–FR39 intent.

---

## Challenges and friction

- **Residual test sharpness:** Oversized-upload e2e remains partly regex-oriented; structured envelope assertions deferred ([`deferred-work.md`](deferred-work.md), Story 2.9).
- **Error taxonomy debt:** Explicit 413 mapping in shared error-code surfaces still deferred from Story 2.2 review ([`deferred-work.md`](deferred-work.md)).
- **Story artifact consistency:** Epic 1 retro asked for status parity and standardized closeout sections; not every Epic 2 story file reflects identical depth or checklist usage—manageable but uneven for archaeology.
- **Documentation volume:** Late-epic docs (2.8–2.10) are correct but increase maintenance obligation—drift risk if runtime changes without updating matrix/fixtures/OpenAPI together.

---

## Key insights

1. **Multi-layer contract truth** (runtime + OpenAPI + markdown matrix + JSON fixtures + tests) catches drift early; keep treating changes to error shapes as a coordinated edit set.
2. **Guardrails belong in CI:** Matrix/fixture set equality and parseability checks are high leverage for doc-heavy stories.
3. **Extension documentation is a deliverable:** Describing hook points (2.10) reduces “paint into a corner” risk without shipping unused queues or DB code.
4. **Deferrals should stay visible:** Track regex-only assertions and taxonomy gaps in `deferred-work.md` or backlog so they do not silently rot.
