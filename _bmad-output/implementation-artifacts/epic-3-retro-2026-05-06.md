## What went well

- **Single primary artifact:** `docs/ux-backlog.md` as the backlog surface (per AC1 recommendation) avoids competing appendices in `epics.md`.
- **Explicit Phase 1 boundary:** AC3 callout preserves **`POST /v1/report/upload`** and published contracts as system of record—consistent with Epic 2’s contract-first posture.
- **Rich traceability rows:** Each UX-DR maps to spec sections, future story titles, and concrete test themes (WCAG 2.2 AA, breakpoints, design-direction references).
- **Discoverability chain:** Root `README.MD` → `docs/ux-backlog.md` → UX spec, epics, Epic 2 integrator docs where relevant.
- **Review closure:** Code review patches fixed relative linking from `docs/` into `_bmad-output/` and made the epics backlog pointer clickable—small edits with outsized navigation value.
- **Non-regression discipline:** Full `homeinspection-api` gates run despite no runtime change—prevents accidental API edits during doc work.

---

## Challenges and friction

- **Cross-root relative links:** Paths that read correctly from repo root in prose do not always resolve as links when the authoring file lives under `docs/` versus `_bmad-output/`—caught in review, worth anticipating on future doc stories.
- **Documentation epic ≠ thin epic:** One story still coordinated UX spec, HTML direction artifact, epics, README, and implementation artifact—the cognitive load is compact but not trivial.
- **Sprint-status header drift:** Deferred housekeeping (`# last_updated` comment vs YAML `last_updated`) remains cosmetic but noisy for audits ([`deferred-work.md`](deferred-work.md)).
- **Completion Notes boilerplate:** Story agent record still carries a generic “Ultimate context engine…” line that adds noise versus Epic 2–style concise completion notes—cleanup optional when editing the file next.

---

## Key insights

1. **Treat multi-root repos as link graphs:** When adding `docs/` artifacts that reference `_bmad-output/`, validate links from the **consumer file’s directory**, not from an imaginary repo-root viewer.
2. **Planning epics benefit from the same exit bar as code:** Status progression (`ready-for-dev` → `review` → `done`) plus optional review caught real usability defects before UI work started.
3. **Epic 2’s contract checklist applies downstream:** Future UI stories should consume upload contracts as documented unless a **versioned** API story explicitly changes them—Story 3.1 already points teams at failure-matrix and OpenAPI.
